# Kvartal

Платформа продаж и рассрочек для застройщика — фронтенд на Nuxt 4 / Vue 3 / TypeScript / Tailwind. Полностью рабочий прототип с мок-данными: шахматка, прайс-листы с черновиком и публикацией, заявки, мастер сделок, договоры и график платежей, доска оплат, документы и полноценный раздел настроек. Бэкенда пока нет — все «API»-вызовы уже оформлены как асинхронные функции, чтобы подключить реальный сервер было заменой одного слоя, а не переписыванием интерфейса.

## Запуск

```bash
npm install
npm run dev
```

Откроется `http://localhost:3300` (порт задан в `.claude/launch.json`; для обычного локального запуска можно `npm run dev -- --port 3000`). Вход — по номеру телефона и коду из SMS; в демо-режиме код `0000` или любой другой подходит, на экране входа есть быстрый вход под демо-пользователями с разными ролями.

## Структура

```
app/
  assets/css/main.css     — дизайн-токены (цвета, шрифты, радиусы), light/dark темы
  components/ui/          — базовый UI-кит: кнопки, поля, таблицы, модалки, дровер, тосты…
  components/layout/      — каркас: боковое меню, шапка, переключатель проекта
  components/units/       — подбор помещений: UnitPicker (шахматка, фасад,
                             план этажа, список), ячейка, фильтры, массовые
                             действия, сравнение, очередь, дровер объекта
  components/settings/    — общий каркас раздела настроек с суб-навигацией
  data/                   — сиды и справочники: seed.ts (детерминированный генератор
                             моковых данных), catalog.ts (пользователи, шаблоны, акции…),
                             nav.ts / settingsNav.ts (структура меню)
  types/models.ts         — доменные типы (Project, Unit, Contract, Payment, …),
                             упрощённая проекция схемы avenue88_schema_v4.sql
  repositories/           — «API»-слой: сейчас читает/пишет мок-данные с имитацией
                             задержки сети; сигнатуры уже такие, какими будут с бэкендом
  stores/                 — Pinia-сторы, единственный источник правды для UI;
                             вызывают repositories, а не мутируют data/ напрямую.
                             board.ts — состояние подбора по скоупам: фильтр,
                             режим, выделение; из него берётся синхронизация
                             шахматки, фасада, плана этажа и карточки заявки
  pages/                  — маршруты (см. ниже)
  layouts/                — default (авторизованный каркас) и auth (экран входа)
  middleware/auth.global.ts — гейт на все страницы кроме /login
```

### Карта разделов

- `/` — дашборд (KPI, воронка заявок, доска оплат, статусы объектов, журнал)
- `/objects`, `/objects/[id]` — проекты (ЖК) и дома с прогрессом наполнения
- `/board` — подбор помещений: шахматка, интерактивный фасад, план этажа и
  список под одним фильтром; массовое выделение, смена статуса и цены,
  сравнение, экспорт в Excel, бронирование и очередь на объект
- `/pricing`, `/pricing/[id]` — прайс-листы: черновик → публикация
- `/leads` — заявки (канбан по этапам); карточка заявки — вкладки Обзор,
  Подбор, Финансы, Документы, История: резюме клиента, чек-лист сделки,
  встроенный подбор, прогноз и факт по деньгам, согласование скидки
- `/clients` — реестр покупателей: таблица с сортировкой, скрытием колонок,
  фильтрами и экспортом; карточка клиента — досье со вкладками Обзор, Объекты,
  Финансы, Договоры, Документы, История
- `/deals/new` — мастер сделок (объект → клиент → условия → договор)
- `/contracts`, `/contracts/[id]` — договоры, график, платежи, документы
- `/payments` — доска оплат по срокам + подтверждение платежей
- `/approvals` — согласование скидок: маршрут Менеджер → Руководитель → Директор
- `/documents` — сформированные документы
- `/reports` — аналитика
- `/users`, `/offices` — пользователи и права, офисы продаж
- `/settings/*` — шаблоны документов, нумераторы, способы оплаты, акции, опции, статусы
  и очередь бронирования, калькулятор условий покупки, настройки мастера сделок,
  автоматизации и лимиты скидок, аккаунт

## Подбор помещений

Шахматка, фасад, план этажа и список — четыре представления одного набора,
а не четыре экрана. Их общее состояние (фильтр, выделение, сравнение) живёт в
`stores/board.ts` по «скоупам»: `board` для страницы шахматки, `lead:<id>` для
карточки заявки, `contract:<id>` для допродажи. Поэтому квартира, выбранная на
фасаде, остаётся выделенной в шахматке и в подборке клиента.

Весь виджет — компонент `UnitPicker`; он используется на шахматке, в карточке
заявки, в мастере сделок и в договоре. Навигация идёт сверху вниз: генплан →
дом → фасад → этаж, цепочка перехода живёт в шапке подбора. Контуры квартир на
фасаде берутся из ручной разметки (`refId = unit:<id>`), а если её нет —
выводятся из полосы этажа, чтобы фасад работал до того, как застройщик
разметит каждое окно; контуры домов на генплане устроены так же
(`refId = building:<id>`).

Клик по помещению открывает мини-карточку: параметры, цена, состояние сделки
и действия — без ухода на другой экран. Горячие клавиши: `B` — бронь,
`D` — договор, `C` — сравнение, `Esc` — сброс. Фильтры каждого менеджера
сохраняются между сессиями в `localStorage` (`composables/usePickerPersistence.ts`),
кроме скоупов конкретных клиентов — там фильтр собирается из их запроса.

## Автоматизации

Правила описаны в `composables/useAutomations.ts` и включаются на
`/settings/automations`. Те, что зависят от времени (истёкшие брони, просрочка
по графику), прогоняются при входе в приложение; остальные срабатывают в момент
действия — в сторах, а не в компонентах, поэтому работают из любой точки:
задача при создании заявки, напоминание через сутки после показа, график
платежей при подписании договора, передача освободившегося объекта первому
в очереди.

## Клиенты

Клиент — это покупатель с договором, а не строка справочника. Его досье нигде
не хранится целиком: `utils/clientProfile.ts` собирает профиль из заявок,
броней, договоров, графиков, платежей, документов и фонда, а
`composables/useClientProfiles.ts` отдаёт готовые профили таблице, фильтрам,
карточке и выгрузке. Поэтому сумма в реестре не может разойтись с договором.

Что считается, а не хранится: статус клиента, менеджер, основной ЖК, объём
покупок, оплачено, остаток, просрочка, ближайший платёж, LTV, средний чек,
общая площадь и скидка, последняя активность.

Кнопка «Досье PDF» печатает `ClientDossier` средствами браузера: отдельного
генератора PDF в проекте нет, а печать в PDF умеет любой браузер — нужно лишь
отдать ему страницу без интерфейса (`@media print` в `main.css`).

## Загрузка и иконки

Каркас приложения не ждёт данные: меню и шапка появляются сразу, на месте
содержимого — скелетон формой будущей страницы (`PageSkeleton`). До гидратации
работает `app/spa-loading-template.html` — тот же каркас на инлайновых стилях.

Иконки собираются в бандл (`clientBundle.scan` в `nuxt.config.ts`), а не
запрашиваются из `api.iconify.design`: в закрытом контуре застройщика внешняя
сеть недоступна, и без бандла интерфейс остаётся без единой иконки.

## Как подключить бэкенд

1. В `app/repositories/*.ts` заменить тела функций (`fetchUnits`, `createReservation`, `publishDraft`, …) на реальные запросы (`$fetch`/`useFetch` к вашему API) — сигнатуры и возвращаемые типы менять не нужно, их уже используют сторы.
2. В `app/stores/*.ts` ничего менять не придётся: они уже вызывают `repositories` асинхронно и ждут `await`.
3. `app/data/seed.ts` и `app/data/catalog.ts` — только фикстуры для разработки; при реальном бэкенде `repositories` перестанут их читать, файлы можно оставить для сторибука/тестов или удалить.
4. Авторизация: `app/stores/auth.ts` уже дергает `repositories/auth.ts` (`requestCode`/`verifyCode`) — подключить реальный SMS/WhatsApp провайдер там же.
5. Приложение сейчас рендерится как SPA (`ssr: false` в `nuxt.config.ts`) — если бэкенд появится и понадобится SSR/SEO для публичной витрины, это можно включить отдельно для соответствующих страниц.

## Design system

Основа — тёплая нейтральная палитра с акцентом `--plum` и дисплейным шрифтом Unbounded (унаследовано от исходного прототипа AVENUE 88), поверх — более структурная, «профессиональная» подача в духе Profitbase: хлебные крошки на каждом экране, пустые состояния с иллюстрацией и действием, черновик → публикация для цен, мастера с нумерованными шагами, единый стиль таблиц с сортируемыми заголовками. Токены — в `app/assets/css/main.css`, прокинуты в Tailwind через `tailwind.config.ts`, поддержаны тёмная/светлая темы.
