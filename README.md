# Kvartal

Платформа продаж и рассрочек для застройщика — фронтенд на Nuxt 4 / Vue 3 / TypeScript / Tailwind. Полностью рабочий прототип с мок-данными: шахматка, прайс-листы с черновиком и публикацией, заявки, мастер сделок, договоры и график платежей, доска оплат, документы и полноценный раздел настроек. Бэкенда пока нет — все «API»-вызовы уже оформлены как асинхронные функции, чтобы подключить реальный сервер было заменой одного слоя, а не переписыванием интерфейса.

## Запуск

```bash
npm install
npm run dev
```

Откроется `http://localhost:3300` (порт задан в `.claude/launch.json`; для обычного локального запуска можно `npm run dev -- --port 3000`). Вход — по номеру телефона и коду из SMS; в демо-режиме код `0000` или любой другой подходит, на экране входа есть быстрый вход под демо-пользователями с разными ролями.

## Структура

```
app/
  assets/css/main.css     — дизайн-токены (цвета, шрифты, радиусы), light/dark темы
  components/ui/          — базовый UI-кит: кнопки, поля, таблицы, модалки, дровер, тосты…
  components/layout/      — каркас: боковое меню, шапка, переключатель проекта
  components/units/       — шахматка: ячейка, фильтры, дровер объекта
  components/settings/    — общий каркас раздела настроек с суб-навигацией
  data/                   — сиды и справочники: seed.ts (детерминированный генератор
                             моковых данных), catalog.ts (пользователи, шаблоны, акции…),
                             nav.ts / settingsNav.ts (структура меню)
  types/models.ts         — доменные типы (Project, Unit, Contract, Payment, …),
                             упрощённая проекция схемы avenue88_schema_v4.sql
  repositories/           — «API»-слой: сейчас читает/пишет мок-данные с имитацией
                             задержки сети; сигнатуры уже такие, какими будут с бэкендом
  stores/                 — Pinia-сторы, единственный источник правды для UI;
                             вызывают repositories, а не мутируют data/ напрямую
  pages/                  — маршруты (см. ниже)
  layouts/                — default (авторизованный каркас) и auth (экран входа)
  middleware/auth.global.ts — гейт на все страницы кроме /login
```

### Карта разделов

- `/` — дашборд (KPI, воронка заявок, доска оплат, статусы объектов, журнал)
- `/objects`, `/objects/[id]` — проекты (ЖК) и дома с прогрессом наполнения
- `/board` — шахматка: два режима отображения, фильтры, бронирование, очередь на объект
- `/pricing`, `/pricing/[id]` — прайс-листы: черновик → публикация
- `/leads` — заявки (канбан по этапам)
- `/clients` — контакты покупателей
- `/deals/new` — мастер сделок (объект → клиент → условия → договор)
- `/contracts`, `/contracts/[id]` — договоры, график, платежи, документы
- `/payments` — доска оплат по срокам + подтверждение платежей
- `/documents` — сформированные документы
- `/reports` — аналитика
- `/users`, `/offices` — пользователи и права, офисы продаж
- `/settings/*` — шаблоны документов, нумераторы, способы оплаты, акции, опции, статусы
  и очередь бронирования, калькулятор условий покупки, настройки мастера сделок, аккаунт

## Как подключить бэкенд

1. В `app/repositories/*.ts` заменить тела функций (`fetchUnits`, `createReservation`, `publishDraft`, …) на реальные запросы (`$fetch`/`useFetch` к вашему API) — сигнатуры и возвращаемые типы менять не нужно, их уже используют сторы.
2. В `app/stores/*.ts` ничего менять не придётся: они уже вызывают `repositories` асинхронно и ждут `await`.
3. `app/data/seed.ts` и `app/data/catalog.ts` — только фикстуры для разработки; при реальном бэкенде `repositories` перестанут их читать, файлы можно оставить для сторибука/тестов или удалить.
4. Авторизация: `app/stores/auth.ts` уже дергает `repositories/auth.ts` (`requestCode`/`verifyCode`) — подключить реальный SMS/WhatsApp провайдер там же.
5. Приложение сейчас рендерится как SPA (`ssr: false` в `nuxt.config.ts`) — если бэкенд появится и понадобится SSR/SEO для публичной витрины, это можно включить отдельно для соответствующих страниц.

## Design system

Основа — тёплая нейтральная палитра с акцентом `--plum` и дисплейным шрифтом Unbounded (унаследовано от исходного прототипа AVENUE 88), поверх — более структурная, «профессиональная» подача в духе Profitbase: хлебные крошки на каждом экране, пустые состояния с иллюстрацией и действием, черновик → публикация для цен, мастера с нумерованными шагами, единый стиль таблиц с сортируемыми заголовками. Токены — в `app/assets/css/main.css`, прокинуты в Tailwind через `tailwind.config.ts`, поддержаны тёмная/светлая темы.
